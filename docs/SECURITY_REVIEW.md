# Security review (P6.1)

Hands-on code audit of everything built in P0.1 to P5.7, done by reading the code. **No test suite, pint, phpstan, flutter or vitest run was executed** (project-owner instruction); the checks that were run are listed at the end and every automated check that should exist is in `MISSED_TESTS.md` (P6.1). Route inventory: `docs/ROUTE_INVENTORY.md`, produced by `scripts/route-inventory.php`.

## 1. Findings and fixes

| # | Severity | Finding | Fix |
|---|---|---|---|
| F1 | Medium | 15 admin routes added in P5.5 / P5.7 (campaign, incentive and referral status / budget / approve / reject, loyalty toggle, quest release / reject, lead status) and 4 content workflow routes (preview, revisions, restore, transition) had no route-level `can:`. Authorization lived only in the FormRequest (or a `Gate::authorize` in the controller), so the P1.1 `AdminRouteAuthorizationGuardTest` would have failed and a future refactor of those requests could have silently opened them. No hole existed today: every FormRequest and controller was read and authorizes. | Route-level `->can()` added (policy ability with the bound model; `viewAny` of the shared content policy for the content routes). Per-model checks stay in the requests. |
| F2 | Medium | No security response headers anywhere (no CSP, HSTS, frame protection, nosniff, referrer or permissions policy). | `App\Http\Middleware\SecurityHeaders` in the `web` group (profile `auto`: admin under the admin path, website elsewhere) and the `api` group. Admin: CSP (`script-src 'self' 'unsafe-eval'`, tiles host from `admin.maps.tile_url`, realtime WebSocket, `frame-ancestors 'none'`), `Referrer-Policy: no-referrer`. Website: CSP with a per-request nonce, no `unsafe-eval`, `strict-origin-when-cross-origin`. API: `default-src 'none'`. All: nosniff, `X-Frame-Options: DENY`, Permissions-Policy, COOP, HSTS only over HTTPS outside local / testing. `CSP_MODE=enforce|report-only|off` and `CSP_EXTRA_IMG_SRC` for rollout. The trip-share inline script now carries the nonce. |
| F3 | Medium | `config/cors.php` allowed every origin, header and method on `api/*`. The API uses bearer tokens (no cookies), so it was not exploitable, but the mobile apps do not need CORS at all. | Origins come from `CORS_ALLOWED_ORIGINS` (default empty = none), explicit methods and headers, `Idempotent-Replayed` / `X-Request-Id` exposed, 10 minute preflight cache. |
| F4 | Medium (feature gap) | Admin IP allowlist (SRS §16.16) was not implemented. | Typed setting `admin_ip_allowlist` (Security tab; comma separated IPs / CIDR, IPv4 and IPv6, empty = off) enforced by `RestrictAdminIp` on the whole admin group (login included, bare 403). The setting refuses an invalid entry and a list that would exclude the saving administrator. |
| F5 | Low | `filesystems.disks.local.serve = true` registered a `GET/PUT /storage/{path}` route (signature protected, nothing minted a signature). | `serve` set to false: the route is gone. |
| F6 | Low | Session cookie `secure` defaulted to null; no trusted-proxy configuration (behind a load balancer `request()->ip()` and `isSecure()` would be wrong, which breaks the IP allowlist, throttling and HSTS); `APP_DEBUG=true` in production was possible. | `SESSION_SECURE_COOKIE` defaults to true in production; `TRUSTED_PROXIES` env (empty = none trusted); boot refuses `APP_DEBUG=true` with `APP_ENV=production` (web requests). |
| F7 | Low | Log redaction covered secrets and OTPs but not phone numbers, e-mail, addresses or coordinates passed as context keys. | `RedactingProcessor` also redacts keys naming phone / msisdn / email / lat / lng / latitude / longitude / address / iban / national_id / account_number. The log scan found no existing call passing them. |
| F8 | Low | Android apps allowed OS backup of app data. | `android:allowBackup="false"` in both manifests (tokens live in `flutter_secure_storage`). |
| F9 | Medium (operations) | Roles stored in a database lacked permissions added after they were seeded (P5.x growth, leads, reports, OTP log): the seeder never touches existing roles by design. | `php artisan admin:sync-role-permissions [--dry-run]` + ledger table `admin_role_permission_grants`. A (role, permission) pair is offered once, so a permission an administrator removed in the panel is never granted again; custom roles and revocations are untouched. The migration backfills the ledger for existing roles except the 11 permissions added after the first seeding; `RoleSeeder` records every default it grants. Run it on every deploy. On the development database it granted 17 missing permissions, a second run granted none. |

## 2. Reviewed and found sound (no change)

- **Routes**: 167 API routes behind `auth:sanctum` all carry a token ability (`customer`, `provider`, or either); 548 admin routes all sit behind `auth:admin` + session tracking + MFA gate and carry `can:` or an explicit `admin.access:self|public` marker (script exits 0). Public routes: OTP request / verify (own limiters, per phone, IP and device), catalogue / content / config (cache headers), health, signed media and receipts, trip-share (43 character token, hashed lookup, throttled, `noindex`, `no-referrer`), payment webhook (signature is the authentication, per-IP limiter), website forms (throttle + Precognition).
- **IDOR**: every service resolves a path uuid through an owner-scoped finder (`findOfCustomer`, `findAssignedToProvider`, `findOfUser`, `findOwned`, `findOfReporter`, policy `manageOwn`) and answers 404 for another person's resource: bookings, offers (booking and offer must match), proofs, booking / chat / ticket / incident attachments, provider documents and vehicle photos, tickets, chat (participant check by token ability, active account, window), payments (`refresh`), payouts and payout methods, saved places, trusted contacts, notifications (recipient type + id), ratings (rater only), receipts, share links, account deletion. The app is taken from the token ability, never from a header.
- **Staged disclosure (I10)**: dispatched but unselected providers see an area-rounded pickup and a request summary only; offers show first name + last initial, photo, rating, no phone; the booking channel is closed to other providers once one is selected; provider position goes only to the customer channel; chat and offer events go to per-party private channels.
- **Private channels**: `RealtimeChannelPolicy` decides on the server from the signed-in account (active, token ability, ownership / participation); admin channel needs `bookings.view` on the admin guard.
- **Signed URLs**: 5 to 15 minute lifetimes, every file route additionally needs the owner's bearer token (admin ones are bound to the admin id and permission); files stream with `nosniff`, a sandboxed CSP, `private, no-store`; uploads are sniffed against the client extension, images decoded with a pixel cap and re-encoded (EXIF dropped), PDFs with active content refused, chat files virus-scanned (scanner unavailable = refused), random storage names, private disks only.
- **Race and money**: offer selection (booking lock, offer lock, conditional update + unique winner marker, expiry re-checked under the lock, lock order booking then offer in accept / reject / withdraw / expire / submit), coupon reservation (coupon row lock, caps re-read inside it, reservation by booking, release / commit / reverse idempotent), payout request (wallet row lock before the balance check and the reservation, idempotency key unique per provider, replay compares amount and method), payout state machine (row lock + status guard on every step, dual approval needs a second admin), ledger posting (accounts locked in ascending id order, balanced entries, unique idempotency key with fingerprint, never updated), webhook dedupe (unique `(gateway, event_id)`, row lock, `processed_at` short-circuit, failure keeps the event for retry, constant-time HMAC, empty secret refused), idempotency middleware (actor + route + key lock, payload hash, 24 h replay), settlement (`booking-settlement:{uuid}` key, `settled_at`), growth hook (marker table in the same transaction), start PIN (attempts counted under the booking lock, `hash_equals`).
- **Sessions and MFA**: `guard->login()` migrates the session id; logout invalidates and rotates the CSRF token; session revocation and suspended admins end the session on the next request; MFA required for `super_admin`, `finance_manager`, `finance_payout_officer`, `system_integration_admin` (setting), with a lock-out after 5 wrong codes. Sanctum tokens carry an expiry; refresh and logout exist; status-based `account.active` blocks suspended / deleting accounts on business writes.
- **Injection / XSS**: no unparameterized user input in raw SQL (interpolations are enum / constant column names); CMS HTML passes the allowlist sanitizer at render time; `{!! !!}` is used only for sanitized HTML, JSON-LD and the admin component renderers.
- **Secrets**: no `.env` tracked; regex sweep (cloud keys, private keys, JWTs, Stripe / Slack / GitHub tokens, Sentry DSN, key-like assignments) over the working tree and the whole git history found only a test fixture password. Gitleaks is not installed. `composer audit`: no advisories. `npm audit`: 0 production vulnerabilities, 2 moderate in the dev-only `vitest` chain (GHSA-xp26-3454-mjgp, Windows path bypass in the mocker). `flutter pub outdated`: patch / minor drift only (31 transitive packages) and `permission_handler` 12 to 13 major available; there is no advisory feed for pub, so review at release time.
- **Log scan**: no OTP, phone, location or token reaches a `Log::` call (SMS failures log the exception message of the gateway, never the number or code); the structured logger redacts by key.

## 3. Residual risks and known limitations

1. **Admin CSP keeps `'unsafe-eval'` and `style-src 'unsafe-inline'`**: the panel uses the standard Alpine build with 86 inline expressions. Moving to `@alpinejs/csp` needs those expressions rewritten as components and a browser pass (P6.3 / P6.4). The website CSP is strict (nonce, no eval). **The CSP was never exercised in a browser**: a blocked resource (map tiles on a custom host, CMS images on a CDN, a chart) would show up as console violations. Roll out with `CSP_MODE=report-only` first; `CSP_EXTRA_IMG_SRC` covers CDNs.
2. **Idempotency middleware**: the lock lasts 30 s and the response is stored after the handler; a request longer than 30 s, or a crash between commit and store, can re-run the handler. Domain-level keys (ledger entries, payouts, offers, bookings) make the money paths safe; non-money writes may repeat.
3. **Ledger idempotency re-check under MySQL REPEATABLE READ**: when `LedgerService::post` runs inside a caller transaction that already read, the unique key still prevents a duplicate entry, but the replay read may not see the winner and the caller gets a 500 instead of a replay. No double posting is possible.
4. **Webhook rejects** (bad signature) store one row each, rate limited per IP; retention is P6.2.
5. **SOS bypasses the general API limiter** by design (`trigger=sos`); a client can send that field on `POST /safety/incidents` to avoid the limit. The service joins repeated presses to the open case.
6. **MFA is required by role, not by permission**: a custom role holding `payouts.approve`, `roles.manage` or `settings.manage` is not forced to enrol unless it is added to `admin_mfa_required_roles`.
7. **Idempotency-Key is not required** on a few mutating routes that are idempotent by nature (profile, devices, availability, withdraw offer, payout-method edits, consents, notification reads) and on `POST /safety/incidents` (deduplicated in the service); see the inventory.
8. **403 vs 404**: provider document / vehicle photo routes answer 403 (policy) for another provider's uuid instead of 404; uuids are random so this is existence disclosure only.
9. **Customer credit usage restrictions are not enforced at spend time** (wallet money is fungible, ADR-198); promotional credit is spent first and expiry reclaims only unspent credit. **No push is sent when a referral / loyalty / quest reward is paid** (only the screens show it).
10. `laravel/boost` is a dev dependency that registers `POST /_boost/browser-logs` in local environments; production images must install with `composer install --no-dev` (P6.4). Behind a load balancer set `TRUSTED_PROXIES`, otherwise the IP allowlist sees the proxy address.
